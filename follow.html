What Follow my game does

Follow my game lets the board analyzer keep up with your game by itself. It notices in the game's log when you make a move, takes a picture of the game window, reads the board from it, and updates the advice. This page says exactly what it reads, what it sees and what it sends, with the code that does each part. The code is loaded from the same files your browser runs, so it can't differ from what's described here.

In short

  • One file, read only. It reads the game log you pick (UE_game.log), and only the lines the game writes after you connect it. It can't open any other file, and it never changes the log.
  • One window, only at moves. It sees only the window you choose to share. It takes a single picture when the log shows a move, or when you press Take a picture now. Nothing is recorded in between.
  • Pictures stay on your PC. The screenshot reader reads each picture inside your browser. Unless you turn on Send the pictures, no picture leaves your PC.
  • Sending is off until you turn it on. With it on, each picture is shrunk to at most 1,280 pixels wide and 220 KB. It's sent with the few log lines that set it off and what the reader made of it. No account, no name, and no address goes with it.
  • Off whenever you like. Stop following and Stop sharing end it at once, as does your browser's own stop-sharing button. The bottom of this page turns it off for good.

What your browser asks you

Chrome or Edge asks you twice, and nothing happens until you say yes both times:

  1. To open a file. You pick UE_game.log, in your Steam library under Torchlight Infinite\UE_game\TorchLight\Saved\Logs. The site gets read-only access to that one file. On your next visit, the browser asks again before the site can read it.
  2. To share a window. You pick the Torchlight: Infinite window. While it's shared, the browser shows that it is, with a button to stop.

Other browsers can't follow a file on your PC, so Follow my game needs Chrome or Edge on a PC. Run the game borderless or windowed: in exclusive fullscreen, a shared window looks black.

How it works, with its code

Each step shows the code that does it, word for word, with its line numbers in the file. It's read from the site just now.

1. You pick the log

connectLog opens the browser's file picker, and the site gets only the file you choose. resumeLog is for later visits: the browser remembers your choice, but asks you again before the site may read it.

2. It reads only the new lines

Once a second, the follower checks whether the log has grown, and reads only the part added since its last look. It starts at the end of the log, so nothing written before you connected is ever read. Each new line is checked against the triggers below. A line that matches nothing is dropped; a line that matches the watch pattern is shown to you on the page. It runs in a background worker, so it keeps up when the tab is hidden.

3. It watches for moves

The triggers are patterns for the lines the game writes when something happens. Each has a kind, the pattern, and a settle time. The prison's lines are added once the new season is live; until then the defaults are the Frozen Canvas's, which test the whole path. You can see and change the triggers on the analyzer, under Triggers and log lines.

When matching lines come in a burst, it waits until the log has been quiet for the settle time, so the animations finish. Then it takes one picture for the whole burst.

4. It takes one picture of the window you shared

connectWindow asks the browser to share a window, which you pick. grab takes a single frame from it, and runs only when a trigger fires or you press Take a picture now.

5. The picture is read into your board

The screenshot reader, running in your browser, turns the picture into a board. The page loads that board and asks for advice. It keeps the pictures only in its list of the last 12, in memory, and they're gone when you close the tab. If Send the pictures is on, the picture is sent after it's read.

6. Sending, only if you turn it on

With Send the pictures on, this shrinks the picture and sends it, with the log lines that set it off and what the reader made of it. client is a random id made in this browser, so pictures from one browser can be told apart.

This is the server's side. It checks every field, keeps only real images within the size limit, drops a picture it already has, and stores the rest. It counts pictures against a scrambled code for your connection that changes every day; your address itself is never stored.

Where sent pictures go

Sent pictures go to the simulator's private database at Cloudflare. They aren't public, they aren't in the site's GitHub repository, and only the simulator's maintainer can download them. They're used to teach the screenshot reader and to check the simulator's rules against the live game.

The store takes at most 300 pictures a day from one connection and 1,500 a day in all, and it holds at most 3,000 at a time.
